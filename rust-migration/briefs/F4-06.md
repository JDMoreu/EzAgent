## Notas específicas
- Sin SDKs: `reqwest::blocking` + un lector SSE propio (`sse.rs`) que entrega eventos `data:` línea a línea sin bloquear más de lo necesario (lee el `Response` como `Read`).
- Define un `trait ChatStream` o tipos de fragmentos (`Chunk`: texto, llamadas a herramienta parciales, uso, `finish_reason`) que el `Messenger` consumirá en F4-07/F4-08; hazlos `pub` y documentados. Traduce el formato de Anthropic al mismo tipo de fragmentos que el de OpenAI, como hace `anthropic_client.py`.
- Implementa el `trait crate::condenser::TextCompleter` (ya existe en `condenser.rs`, no lo edites) para ambos clientes: respuesta corta en streaming, `temperature=0`, y `reasoning_effort=none` para los proveedores `opencode`/`openai`.
- `friendly_llm_error` y los textos de error deben ser idénticos a los del Python (clasificación por código HTTP y por texto del error). Las claves de API nunca van a logs ni a los mensajes.
- Para las pruebas unitarias usa un servidor HTTP falso con `std::net::TcpListener` en un hilo que sirva SSE.

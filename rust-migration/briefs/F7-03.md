## Notas específicas
- **Privacidad:** copia el perfil real a un directorio temporal y trabaja solo sobre la copia; no subas, no imprimas ni commitees contenido del usuario (en el informe, solo nombres de archivo, conteos y diferencias estructurales). **Ida:** Rust lee cada artefacto de la copia (cargar configuración, historial, tareas, memoria, diario, tablero) sin errores ni pérdidas. **Vuelta:** Rust escribe cada artefacto (modificando algo) y el Python (con el `.venv`) lo lee y obtiene lo mismo; y al revés. **Enjambre mixto:** el `ezs` de Python habla con el servidor de Rust y el `ezs` de Rust con el servidor de Python (mismo protocolo, token, `endpoint.json`): `join`, `next`, `done`, `post`, `status` dan las mismas respuestas. Automatiza todo en `parity/compat/run_compat.py` (que use binarios Rust ya compilados y el `.venv`) y deja una prueba Rust donde tenga sentido.
- Cada incompatibilidad: corrígela en Rust (salvo que sea un error del Python: entonces se reproduce y se anota en `rust-migration/python-quirks.md`). Informe: tabla artefacto × dirección (Python→Rust, Rust→Python) con resultado, y las del enjambre. `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` en verde.

## Criterios de aceptación
- Todo lo público del Python está portado, con los mismos textos y valores por defecto.
- `cargo fmt --all`, `cargo clippy -p <crate> --all-targets -- -D warnings` y
  `cargo test -p <crate>` limpios, ejecutados desde `rust/`.
- Informe en `rust-migration/reports/F7-03-r1.md` y un commit en tu rama.

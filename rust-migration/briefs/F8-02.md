## Notas específicas
- El modo `eval` reproduce exactamente lo que hace `provider.py`: perfil de usuario temporal (nunca la memoria, skills ni `system.md` reales), `context` devuelve el prompt de sistema y las herramientas que vería el modelo sin llamar a ningún LLM; `live` hace una sola llamada al LLM configurado, registra las herramientas pedidas sin ejecutarlas (resultado simulado) y corta antes de la segunda llamada. Las claves nunca se imprimen ni se registran.
- Comprobación: `npx promptfoo eval -c promptfooconfig.offline.yaml` (Python) y `-c promptfooconfig.offline.rust.yaml` (Rust) desde `evals/` con su `node_modules` dan **los mismos resultados caso por caso** (pega la tabla en el informe); además una prueba Rust que compare la salida de `eval --mode context` con la de `provider.py` en modo `context` para varios casos (mismo prompt de sistema y mismas herramientas, o diferencia documentada si el prompt de Rust ya difiere a propósito). No ejecutes el modo `live` contra un LLM real salvo que exista configuración en el perfil, y en ese caso solo 3 casos. `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test -p ez-app` en verde.

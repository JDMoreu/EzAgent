## Decisiones
- `SwarmServer` recibe `Arc<SwarmService>`: Python comparte el mismo objeto entre el servidor y la app; en Rust la propiedad compartida se modela con `Arc`. El `stack` de F4-13a tendrá que guardar el servicio también como `Arc`.
- Un hilo por petición (como `ThreadingHTTPServer`) y un hilo aceptador llamado `ezagent-swarm`, igual que Python.
- `tiny_http` no permite fijar el `timeout = 15` de lectura de cada petición del handler de Python; una conexión local colgada ocupa solo su hilo y no frena a las demás. Riesgo bajo al escuchar únicamente en loopback.
- Cualquier método distinto de `POST` responde 404 (Python responde 404 a `GET` y deja el 501 de `BaseHTTPRequestHandler` para el resto); el contrato solo define `POST /v1`.
- Si `SwarmService::handle` devuelve un error interno, el servidor responde 500 con `{"ok": false, "text": ""}` (Python cerraría la conexión sin respuesta) para que `ezs` reintente en vez de agotar su timeout. Se registra el error, nunca el cuerpo ni el token.
- `read_port` devuelve `u16` y solo acepta dígitos ASCII (Python acepta dígitos Unicode y puertos de cualquier tamaño); `endpoint.json` siempre publica un puerto ASCII válido.
- Un `EZS_SEAT` ilegible o no UTF-8 cuenta como sin token (Python deja escapar `UnicodeDecodeError` de `_token`, que solo captura `OSError`).
- Una respuesta JSON que no sea objeto se trata como fallo de conexión y se reintenta (Python lanzaría `AttributeError` sin capturar).
- Se añadieron `endpoint_path_from`, `read_port_from`, `token_from` y `main_with` como puntos de inyección para probar entorno y salidas sin tocar variables de proceso.

## Pendiente o riesgos
- Las pruebas de paridad contra `parity/fixtures/swarm.jsonl` no se escriben en esta fase.
- `SwarmServer` no reproduce el `timeout = 15` de lectura por petición porque `tiny_http` no lo expone; una conexión local colgada retiene su hilo (no bloquea al resto).
- Puertos mayores de 65535 o con dígitos Unicode en `endpoint.json` se interpretan como 0 (Python los aceptaría hasta fallar al conectar); no ocurre con el archivo que publica EzAgent.
- El `stack` de F4-13a debe adaptarse a `Arc<SwarmService>` y al `SwarmServer` de este puerto.
- El texto de error de `_publish` usa el `Display` de `std::io::Error`, no el de `OSError` de Windows (misma aproximación que el resto de la migración).

## Decisiones
- `MemoryTimestamp` (`Now`/`DateTime`/`Text`) sustituye a `datetime | str | None`. No se representa un `datetime` naive: el Python lo trata como UTC, pero la API Rust solo usa instantes con desfase; los llamadores pueden pasar el texto ya formateado. Marcado `// DECISION`.
- Los `RuntimeWarning` del Python se registran con `tracing::warn` (no hay mecanismo de warnings en el crate).
- En `_init_db` se trata cualquier error de `rusqlite` al crear FTS5 como el `OperationalError` del Python: se guarda `fts_error`, se retiran los triggers y `recall` cae a LIKE. La alternativa estricta exigiría distinguir códigos de error sin cambiar el resultado práctico.
- `last_backend` queda tras un `Mutex` (los manejadores del registro son `Fn` y no `FnMut`); se expone con `last_backend()`. Mismo valor y semántica que el atributo del Python.
- Los métodos de escritura devuelven `Result<_, String>` (el Python propaga `OSError`); en los manejadores ese error termina como `outcome="failed"`, igual que una excepción no capturada en Python.
- `read_text` registra y devuelve `""` ante errores distintos de «no existe»; el Python lanzaría. Solo alcanza archivos ilegibles (permisos), que en el Python romperían el turno.
- `build_memory_tools(config, store, confirm, confirmation)` recibe las opciones por posición (Rust no tiene argumentos con nombre) y el almacén como `Arc<MemoryStore>`.
- `_safe_ask` captura pánicos del callback para reproducir el `except Exception: return False` del Python.
- Escritura atómica: archivo temporal propio en la misma carpeta, `write_all` + `sync_all` + `rename`; si el `rename` falla se borra el temporal (archivo propio), nunca el archivo del usuario.
- Los regex de Python con lookaround (`(?<!\d)`, `(?!\w)`) se portan comprobando los caracteres vecinos a mano, porque `regex` no admite lookarounds y `fancy-regex` no está declarado en el crate.
- El comando de consola `python -m ezagent.agent.memory wipe` (`build_parser`, `_wipe_command`, `main`) no se porta: imprimir con `println!` solo está permitido a `ezs`/`ezagent_voice` y este crate no tiene binario. Queda anotado abajo.

## Pendiente o riesgos
- El comando `wipe` de consola no se porta (ver Decisiones); si se necesita, debe vivir en el binario `ezs`, que sí puede imprimir.
- Un `datetime` naive del Python (interpretado como UTC) no tiene equivalente en `MemoryTimestamp`; los llamadores Rust deben pasar un instante con desfase o el texto ya formateado.
- `from_utf8_lossy` agrupa los bytes inválidos distinto que `errors="replace"` de Python en secuencias UTF-8 malformadas; solo afecta a archivos editados con una codificación rota.
- Los errores de lectura distintos de «no existe» se registran y se tratan como archivo vacío; el Python lanzaría `OSError` y cortaría la operación.
- `scan_diff.py` (regla de tamaño del `gate.ps1`) sigue marcando `rust/crates/ez-agent/src/skills.rs` (863 líneas) y `rust/crates/ez-agent/src/tools_d.rs` (897), ya por encima de 600 antes de esta tarea y fuera de sus archivos; los seis `.rs` de esta entrega cumplen el límite.

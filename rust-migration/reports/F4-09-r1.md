## Decisiones
- `# DECISION`: `herdr` y `callbacks.swarm` entran como traits locales (`HerdrApi`, `SwarmStack`). `ez-agent` no puede depender de `ez-herdr`/`ez-swarm` (aún no existen en esta rama) y el Python usa `getattr`; un `None` devuelve vacío, igual que allí.
- `# DECISION`: `build_herdr_tools`/`build_swarm_tools` son de F4-12b/F4-13b y hoy son esqueletos vacíos. El runtime acepta grupos adicionales con `add_tool_group(ToolGroupBuilder)` y los reconstruye con el resto; no se tocó ningún archivo ajeno.
- `# DECISION`: `ConfirmationGate` es un trait que `ConfirmationManager` implementa. El Python asigna `runtime.confirm = ScriptedConfirm(...)` en las pruebas; esta es la costura equivalente y permite además desactivar la confirmación con `None`.
- `# DECISION`: `bulk_forced` no toca `policy.rs`: `effective_bulk` devuelve `umbral + 1` cuando el umbral no es cero (o el número real con umbral 0), que reproduce exactamente `_FolderBulk.__gt__`.
- `# DECISION`: `on_confirm_ask` siempre recibe `(summary, strong, token)`; el Python intenta 3 argumentos y cae a 2 con `TypeError`. Rust no tiene esa reflexión y la UI antigua puede ignorar el token.
- `# DECISION`: `RuntimeCallbacks`, `agent_at` y los accessors `config`/`voice_config`/`callbacks`/`registry`/`confirm_gate` sustituyen a los atributos mutables del Python; `set_config`/`set_voice_config`/`set_registry`/`set_confirm_gate` permiten el mismo cambio en caliente controlado.
- `# DECISION`: `execute` toma una foto de `AgentConfig` y del registro al empezar (Rust multihilo). El Python lee los atributos vivos; la diferencia solo aparecería si otro hilo recarga permisos justo durante una herramienta.
- `# DECISION`: los callbacks y constructores de grupo se envuelven en `catch_unwind` donde el Python captura `Exception` (grupos de herramientas, `pending_tasks`, `swarm.active`, la confirmación, `get_last_user_text`). Un pánico no deja el mutex envenenado porque se captura.
- `# DECISION`: `parse_arguments` reproduce `json.loads(raw_arguments or "{}")`: todo valor falsy que no sea dict llega como `{}` (0, false, `[]`, `""`, `null`), y un valor truthy que no es texto da «Argumentos JSON inválidos.».
- `# DECISION`: `system_prompt` y `prompt_parts` capturan el pánico del ensamblado para reproducir el `except` del Python con su texto de respaldo.
- `# DECISION`: `close` es un no-op: el `AuditLog` de Rust abre el archivo por línea y no mantiene descriptores. Se conserva el método por contrato.
- `# DECISION`: `_warned_system_md` no se porta: el Python lo asigna en el constructor y no lo lee nunca.
- `# DECISION`: `_agent_at` (privado y sin llamadas en el Python) se incluye como `agent_at` porque es barato y F4-12 lo puede necesitar.

## Pendiente o riesgos
- **Grupos de Herdr y enjambre**: `_rebuild_tools` no llama a `build_herdr_tools`/`build_swarm_tools` porque esos archivos son esqueletos de F4-12b/F4-13b. Hasta que la app registre esos grupos con `add_tool_group`, `voice_control` y `swarm` no existen en el registro y `base_tool_schemas` devuelve 3 de los 5 nombres base (`web_search`, `fetch_page`, `read_file`). Es la única diferencia funcional con el Python y desaparece al integrar F4-12b/F4-13b.
- **Callbacks del constructor sin uso**: `last_summary`, `mute`, `request_close`, `mic_mute`, `remember_task`, `enqueue_chain`, `deliver_answer`, `prewarm_chain` y `async_launch` se guardan y se exponen con `callbacks()`, pero el runtime no los invoca (en el Python los consume `build_herdr_tools`, también de F4-12b).
- **`_agent_at` no se usa** en el Python actual; se porta por completitud.
- **`_preserve_session_paths`**: está portado (comparación de las nueve rutas más `paths.read_roots`, aviso por auditoría y `on_warn`), pero no tiene prueba dedicada porque exige dos recargas reales de `permissions.toml`; se cubrirá en la fase de paridad.
- **Confianza en la captura de pánicos**: los callbacks de la app se ejecutan con `catch_unwind`; un callback que entre en pánico se trata como respuesta vacía o rechazo, no como error visible.
- **`pending_notify_address`**: se protege el callback con `catch_unwind`, pero la dirección del agente debe seguir siendo la de `watch_agent`; si la app nunca lo llama, la respuesta es `None`.
- **Paridad**: no se escribieron pruebas contra `parity/fixtures` (fase posterior). Los textos y valores por defecto están copiados del Python y cubiertos por pruebas propias.

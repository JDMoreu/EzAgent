## Decisiones
- **Binario de arnés dentro de `ez-app`**: el brief permite `rust/crates/**/src/**`
  solo para corregir incompatibilidades y prohíbe tocar `Cargo.toml`. Un binario
  auto-descubierto en `src/bin/` usa las dependencias que ya declara `ez-app`
  (sin manifiesto nuevo) y ejecuta las APIs del port, no SQL a mano. Es la
  herramienta de `parity/compat`; no lo usa la app.
- **`join`, `post` y `status` del brief**: el `ezs` del baseline no tiene esos
  nombres; el alta de miembros es `SwarmService.start` (los dos servidores
  siembran el mismo enjambre y emiten los tokens) y los comandos equivalentes
  son `ezs board` (estado), `ezs say` (mensaje) y `ezs me` (instrucciones de
  ingreso). Se prueban esos, más `next`, `done`, `inbox`, `lock`, `unlock` y un
  comando desconocido.
- **Fechas fijas**: las escrituras usan instantes fijos (chat 1700000000.125,
  tareas 1700000100, memoria 2026-11-01) para comparar valores exactos; la
  memoria usa una fecha dentro de la retención de 180 días para que
  `purge_old` no borre la fila recién insertada.
- **Normalización mínima**: en `board.db` se sustituyen tiempos, id de enjambre
  y dígito del token; en el transcript del enjambre, token, id, puerto, rutas
  temporales y edades. Todo lo demás se compara exacto.
- **`journal` del Python**: `Journal` no expone un lector público; el arnés usa
  su `_load_entries` (mismo formato que lee el port) solo para comparar.
- **Estado de OpenCode**: se compara byte a byte (`model.json`) y el valor de
  `XDG_STATE_HOME`; es un artefacto de `%LOCALAPPDATA%` que EzAgent escribe para
  el CLI externo.
- **`opencode-state` y `handoff`**: el primero se prueba; los `.md` de
  `handoff` son texto libre escrito para `hc` y no se releen, así que no tienen
  formato que compatibilizar.
- **`engine.json`/`config.json`**: legado que ni el Python ni el Rust actuales
  leen (`grep` sin lectores); se copian al temporal para no alterar el perfil,
  pero no se comparan. `skills/` y `tools.d/` son árboles de instrucciones y
  ejecutables, no datos serializados.

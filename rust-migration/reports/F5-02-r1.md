## Decisiones
- `UiState` usa un único `parking_lot::Mutex` con la cola dentro del estado (el Python usa `queue.Queue` + `RLock`): mismo orden de eventos y sin bloqueos del hilo de UI.
- El reloj inyectable de Python (`clock=`) se porta como `UiState::with_clock`; `UiState::new` usa `ez_core::metrics::monotonic`.
- No se portan `_pending_base` ni `_pending_at`: en Python se inicializan y se reasignan, pero ningún camino los lee. El evento `"menu"` tampoco se porta: ninguna función de `state.py` lo publica y `drop.py` lleva su propio `_menu_open`, así que `menu_open` queda siempre en `false` (como en Python con los llamadores actuales).
- `raise_error(kind, now)` exige el tipo (el Python tiene default `"transient"`); `set_app_state("error"/"cancelled")` reproduce que el Python llame a `raise_error` **sin** `now` (usa el reloj, no el `now` recibido).
- `FlowField::new(layout, aspect, seed)` recibe `seed: u64`; `Default` es `("pill", None, 7)`.
- `COLORS` (dict de tablas NumPy) se expone como `colors(theme) -> [Palette; 7]`, reutilizando la tabla ya portada en `model::drop::palette` (F5-03) en vez de duplicar los 70 colores.
- `PRESETS`, `PRESET_LABELS`, `STATE_WORD`, `POSE_FOR_STATE` e `INK` se portan como arrays ordenados; los `dict` de Python conservan el orden de inserción.
- `INK` (dict de tuplas) se porta como `Tints` con campos nombrados; `ink()` devuelve la misma struct con `mint` y `muted` tomados de `tokens::palette`.
- `orbit_tile` no conserva la caché global `_TILES` de Python: es pura y el llamador puede cachear por la misma clave.
- Precisión: el brief pide `f32`, pero NumPy promociona `float32 - int32` a `float64` dentro de `_vn`, y en `render` la imagen acaba en `float64`; `FlowField::field`/`render` reproducen **esa** mezcla (el Python es la especificación). `orbit_tile` sí es todo `f32`, como el original.
- `flow.rs` (539 líneas) y `state.rs` (463 tras el split) quedan bajo 600; el RNG y las pruebas se separaron en `flow/rng.rs` y `state/tests.rs`, como permite el brief para módulos grandes.
- `field` comprueba que las dos rejillas tengan la misma forma con `assert_eq!`; el Python lanzaría un error de broadcast en el mismo caso.

## Pendiente o riesgos
- La comparación contra los PNG dorados `parity/golden/hud/*.png` queda para la fase de paridad: aquí no se compone la barra entera (es F5-04). Los oráculos cubren el campo, el render y la capa de órbita por separado.
- `FlowField::render` devuelve `Array3<f64>` (como el Python); F5-04 debe hacer el `clip(img * bright, 0, 255) as u8` de `render_fluid`. `field`/`render` piden `ArrayView2<f32>` (la cuadrícula gruesa de `drop.py`).
- `segment_distance` se portó dentro de `marks.rs` porque `ez-gfx::icons` (F2-11) aún está vacío; cuando llegue, conviene reutilizarlo y borrar la copia local.
- El RNG de NumPy es privado de `flow`; si otro módulo necesita `default_rng`, habría que moverlo a un sitio común (requiere un archivo fuera de esta tarea).
- `parse_hex` no reproduce los casos exóticos de `int(s, 16)` con signos o guiones bajos (`"-F"`, `"F_F"`); los valores normales (`#RGB`, `#RRGGBB`, `RRGGBB`) sí coinciden.
- `set_app_state(state, now)` descarta `now` al levantar el error (usa el reloj), igual que el Python; si algún llamador pasa un `now` simulado, el error no sigue ese reloj.

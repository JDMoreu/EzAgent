## Decisiones
- `# DECISION` (generadores): el reloj se congela en `2025-01-01T00:00:00+00:00` (archivos/skills) y `2025-01-01T12:34:56+00:00` (hora), igual que `_common`. En Windows `TZ` no se aplica con `time.tzset`, así que la rama «hora local» de `get_datetime` fija UTC en el propio `datetime`; es la zona que `_common` pretende imponer y evita fixtures dependientes del equipo.
- `# DECISION` (`tools_fs`): `send2trash` se sustituye por un movimiento a `<tmp>/trash/<caso>/NNN-nombre` que registra la ruta; `os.startfile` se sustituye por un registro. El flujo de Python (comprobar existencia, llamar al envío, diario) se ejecuta igual.
- `# DECISION` (`tools_fs`): las descripciones se calculan **antes** del manejador, como hace `AgentRuntime.execute`; así el `ToolInfo` de `delete_path`/`write_file`/`copy_path` refleja el estado previo y no el posterior.
- `# DECISION` (`tools_fs`): además de `asdict(ToolInfo)` se guarda `bulk_forced` (`type(info.bulk).__name__ == "_FolderBulk"`). Es la única forma de fijar en JSON el `__gt__` especial que el port de Rust modela con `ToolInfo.bulk_forced`.
- `# DECISION` (`tools_fs`): `_count_items` se prueba con 5001 archivos reales una sola vez; el resto de umbrales se fijan con `_count_phrase`. Crear 5000 archivos por caso habría inflado el fixture sin aportar más ramas.
- `# DECISION` (`tools_skills`): el árbol de las cinco skills se publica en un caso `fixture_tree` (incluye el binario como `bytes_hex`) para que el `.jsonl` sea autocontenido; los demás casos lo referencian como `skills: "default"`.
- `# DECISION` (`tools_web`): no se usa red. `httpx.MockTransport` sirve las páginas, `socket.getaddrinfo` se sustituye por un DNS falso y `ddgs` por motores de prueba. Los errores de las funciones que **lanzan** (`validate_public_target`, `pinned_request_target`, `_extract_text`, `DdgsSearchProvider.*`) se registran con `add_error` y el texto exacto; los de las herramientas se fijan dentro del `ToolResult` porque el Python también los devuelve así.
- `# DECISION` (`tools_web`): el caso `DdgsSearchProvider/state/*` existe solo para fijar la rama interna «un motor que falló se descarta» (`_engine = None`); se marca con `after_error: true`.
- `# DECISION` (`tools_web`): `run_fetch_page` recibe un `transport` de prueba; el camino de producción con IP fijada, `Host` y SNI se cubre por `pinned_request_target` y por el manejador de `fetch_page` de `build_web_tools` (que usa `httpx.HTTPTransport` sustituido).
- `# DECISION` (`tools_swarm`): se reutiliza `swarm_board.dump_board` para volcar el tablero (ya usado por los generadores del dominio `swarm`); el Herdr es falso y no se arranca el servidor ni el supervisor.
- `# DECISION` (`tools_swarm`): los incidentes se siembran sin `resets` para que el texto de `recovery.resolve` no dependa de la zona horaria del equipo (la rama de `resets` ya está fijada en el dominio `swarm`).

## Pendiente o riesgos
- `tools_core.get_datetime` sin zona: el fixture fija UTC como «hora local» (ver decisión). Si el arnés de paridad de Rust ejecuta con otra zona local, debe comparar esa rama con una zona UTC inyectada o normalizar el resultado; las ramas con zona IANA no dependen del equipo.
- `zoneinfo` depende de la base tz del sistema: las fechas usadas son de 2025 y los offsets son estables, pero un cambio de tzdata podría moverlas. `Pacific/Kiritimati` y `Asia/Tokyo` están en +14 y +9 sin horario de verano.
- `tools_web._extract_text` usa `beautifulsoup4 4.15.0` + `lxml`: el texto extraído puede variar entre versiones. El arnés debe fijar esas versiones o comparar solo el texto normalizado.
- No hay casos de enlaces simbólicos de Windows (`list_dir`/`_entry_payload` tipo `link`, borrado de un enlace, copia de un enlace): crearlos requiere privilegios y no son deterministas en todos los equipos. Queda como riesgo del port.
- Ramas de error de disco poco provocables sin privilegios/ACL: `OSError` de `os.scandir`, `_discard_temp` cuando la Papelera falla, `entry.stat` de una entrada que desaparece, `open_path` sin `os.startfile` (fuera de Windows) y `load_skill` con un error inesperado de disco. El código de Rust debe conservarlas aunque no tengan fixture.
- `tools_skills.run_skill_script` guarda la aprobación **antes** de comprobar el intérprete: con `_python_interpreter() is None` la aprobación queda escrita aunque el script no se ejecute. El caso `run-no-interpreter` lo fija; es comportamiento del Python, no un fallo del generador.
- `tools_swarm` no cubre `start` cuando `SwarmService.start` falla a mitad (se limpia el estado con `stopped`) ni la rama `except Exception` de `_handle` («Error del enjambre: …»): haría falta un tablero que falle de forma inyectable. Son ramas defensivas; el port debe mantenerlas.
- `tools_swarm` fija el estado interno del motor de `ddgs` con un caso `after_error`; el arnés de paridad tendrá que reproducir el fallo y consultar el motor, no solo comparar el JSON de una llamada.
- Los generadores pesan entre 500 y 1150 líneas. El límite de 600 líneas de `AGENTS.rust.md` §4 es para módulos `.rs`; los generadores existentes ya superan ese tamaño (por ejemplo `journal.py`, 701 líneas).
- No se generó `parity/golden`: el brief no lo pide para este dominio.

# F8-02 — Modo eval en Rust (context y live) y proveedor de promptfoo que lo llama (ronda 1)

## Resultado
- Brief/tarea: F8-02
- Estado: completado

`ezagent-voice eval --mode context|live` reproduce `evals/provider.py` sobre el
código Rust: perfil de usuario temporal, `AgentRuntime` y `Messenger` reales,
salida JSON con el mismo contrato. `evals/provider_rust.py` llama al ejecutable
y `promptfooconfig.offline.rust.yaml` / `promptfooconfig.rust.yaml` corren las
mismas pruebas con ese proveedor. La corrida offline de promptfoo da **los
mismos resultados caso por caso** que la de Python (11 verdes y las mismas 4
fallas del baseline, ver tabla) y las 15 salidas son idénticas salvo la hora del
prompt.

## Decisiones
- `--mode` va por línea de comandos y el resto por stdin; `provider_rust.py` resuelve `user` (`str(vars.user or prompt or "")`) y elige el modo con el mismo criterio que `provider.py` (`context` solo si se pide).
- El `--help` del programa principal no menciona `eval`: su texto es el de `argparse` y hay una prueba de paridad que lo compara palabra por palabra. `eval --help` tiene su propia línea de uso.
- El guardián construye el cliente del proveedor porque `ez-llm` deja `build_client` en `pub(crate)`; se copian sus cabeceras (`user-agent`, `x-opencode-session`, `anthropic-workspace-id`), la clave por omisión y los tiempos. Si `ez-llm` cambia esas cabeceras, hay que copiarlas aquí.
- Nombres de carpeta temporal a mano (pid + reloj + contador): la crate `tempfile` no está declarada en `ez-app`.
- Borrado recursivo con `remove_file`/`remove_dir` sobre carpetas propias: `remove_dir_all` está prohibido por la puerta y esto solo toca el perfil de arena del eval.
- El historial acepta la lista o su JSON en texto; los elementos que no son objetos se descartan (promptfoo solo manda dicts, y `dict(item)` del Python no aplica).
- `_RecordingRuntime` no apunta las llamadas: el Python las guarda y nunca las usa.
- Los errores del binario salen como `{"error": "RuntimeError: ..."}` con código 1; `provider_rust.py` los devuelve tal cual (el prefijo de clase es el único texto que no se puede reproducir sin la excepción real).
- Modo `live`: el juez `call_grader` no se porta porque el contrato del subcomando es `context|live` y el binario no necesita un modelo juez; el YAML live usa `provider.py:call_grader`.

## Pendiente o riesgos
- El modo `live` no se probó contra un modelo real por falta de configuración en
  el perfil de arena; el código path está cubierto por el contrato (una sola
  llamada, herramientas simuladas, corte antes de la segunda). Probarlo con
  `EZ_EVAL_PYTHON`/clave real cuando haya perfil.
- `provider_rust.py` duplica 4 líneas de `build_client` (cabeceras) porque
  `ez-llm` no lo expone; anotado arriba.
- Si el `system.md` real contiene una línea que empiece por «Hoy es », la prueba
  de integración la descarta junto con la hora; es una normalización deliberada.
- Las 4 fallas del contrato offline son del baseline de Python y quedan
  registradas aquí; `rust-migration/python-quirks.md` no está en la lista de
  archivos de este brief, así que no se tocó.

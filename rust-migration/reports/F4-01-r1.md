## Decisiones
- `// DECISION`: los módulos se parten (`segmenter/tests.rs`, `capture/mic.rs`, `turn/features.rs`) para respetar el límite de 600 líneas y 60 líneas por función.
- `// DECISION`: `SmartTurn::new` **no** descarga el modelo ni llama a `resolve_model_path`: este crate no tiene backend ONNX (`ort` no es dependencia aquí), así que bajar 8,7 MB no serviría. `resolve_model_path` queda portado y probado por compilación para cuando se cablee `ort`. El aviso es el del Python: `Smart Turn no disponible; uso solo el silencio: …`.
- `// DECISION`: `SmartTurn::with_model` no precalienta; es la costura de inyección (pruebas y cableado futuro), no la carga real.
- `// DECISION`: `prepare` descarta el byte suelto final en vez de lanzar como `np.frombuffer`; el segmentador siempre entrega PCM par.
- `// DECISION`: `reflect_pad` rellena con ceros si el audio tiene ≤ 200 muestras (el Python lanza); es inalcanzable desde `prepare`, que siempre pasa 8 s.
- `// DECISION`: `resample_linear` con `from_rate == 0` devuelve el audio tal cual (el Python lanzaría `ZeroDivisionError`) para no entrar en pánico desde el hilo de audio.
- `// DECISION`: `MicCapture::close` es un no-op: `cpal` no tiene `terminate`; el stream se cierra al salir de `stream`.
- `// DECISION`: `InputDevice.rate/channels` salen de `default_input_config` de `cpal` (PortAudio exponía `defaultSampleRate`/`maxInputChannels` directamente).
- `// DECISION`: el umbral de `SmartTurn` vive en `Arc<Mutex<f64>>` con `threshold()`/`set_threshold()` porque `app.py` lo cambia en vivo (`detector.threshold = …`).
- `// DECISION`: `to_mono_i16` convierte I16/F32/I32/U16; un formato exótico devuelve silencio en vez de romper el hilo de audio.
- `shortcut:` la DFT de 400 puntos es directa O(N²) (≈64 M de multiplicaciones por ventana). Si Smart Turn se enciende en producción, cambiar a FFT mixta (400 = 2^4·5^2) o Bluestein.
- No se añadieron entradas a `python-quirks.md`: no encontré ningún error del Python que reproducir.

## Pendiente o riesgos
- `SmartTurn` no ejecuta inferencia todavía: falta cablear `ort` (fuera de este crate y de su lista de dependencias). El hilo `ezagent-turn`, el trait, el umbral en vivo y el `Probe` están listos; `probability` devuelve `Smart Turn no está cargado` mientras no haya modelo.
- La DFT directa es el punto caliente: en release ronda decenas de ms por ventana de 8 s y en debug ~0,3 s (por eso las pruebas preparan pocas ventanas). No es aceptable para producción; queda el `shortcut:` para sustituirla por una FFT.
- `pcm_rms`/`pcm_is_weak` pueden diferir de numpy en ~2e-7 por el orden de suma en `f32`; las pruebas de paridad deberán comparar con tolerancia.
- `MicCapture::stream`, `list_input_devices` y `pick_input_device` no se probaron con micrófono real en esta sesión: compilan y la lógica pura está probada con audio sintético, pero la apertura de `cpal` (tasa/canales del dispositivo) queda para la validación manual.

## Decisiones
- `// DECISION`: `brand.mark_image` aún no existe (F2-11 sigue como esqueleto), así que el respaldo dibuja la misma silueta (cuadrado redondeado, degradado de grafito y dos gotas de menta) sin depender de `ez-gfx`.
- `// DECISION`: Pillow usa LANCZOS; aquí se usa un bilineal propio porque `ez-app` solo declara `png`. El tamaño final y el canal alfa son los mismos.
- `// DECISION`: `load_icon_image` acepta solo PNG (el asset real es `assets/icon.png`); cualquier error de lectura o decodificación cae al respaldo, como el `except Exception` del Python.
- `// DECISION`: `start()` no espera al registro de Win32 y devuelve `true` si el hilo arrancó, igual que Python (que crea el `Icon` y no espera a `run()`). Así no se bloquea el hilo de UI; si `Shell_NotifyIconW` falla, `running()` pasa a `false`.
- `// DECISION`: `TrayIcon` implementa `Drop` para soltar el icono; el Python confía en que el proceso termine, pero un objeto Rust puede destruirse en caliente.
- `// DECISION`: `available()` devuelve siempre `true`: `Shell_NotifyIconW` es parte de Windows, no hay un `pystray` opcional que pueda faltar.
- `// DECISION`: `error` es un accesor (`error()`) en vez de un campo público, porque lo escribe el hilo del atajo.
- `// DECISION`: los módulos se parten en `tray.rs` (531 líneas), `tray/image.rs` (256) y `tray/icon.rs` (99) para respetar el límite de 600 líneas.
- Los textos del menú, del tooltip y de los errores están copiados literalmente del Python (incluido `EzAgent · activo` y `¿lo usa otra app?`).

## Pendiente o riesgos
- El registro real de un atajo global no se prueba automáticamente: tomaría una combinación del escritorio del usuario. El camino de error (spec inválido) sí está probado y el registro/desregistro usa las mismas banderas que el Python.
- La interacción con el menú (clic derecho, selección) no está automatizada; se validó el registro y el retiro del icono con una prueba manual. El orden y los textos del menú están en una tabla comprobable.
- El respaldo visual no es idéntico píxel a píxel al de `brand.py`; cuando F2-11 esté portado se puede reutilizar `ez_gfx::brand`.
- `fill_tip` corta a 127 unidades UTF-16; un par sustituto partido en el límite se mostraría como reemplazo (el Python delega el corte a pystray/Windows).

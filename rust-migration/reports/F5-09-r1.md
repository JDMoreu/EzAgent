## Pendiente o riesgos
- El puente `pointer/activation.rs` sigue vivo: `pointer.rs` llama a `activation::{save, start_test, begin_text_edit, set_slider_from_x, set_meter_from_x}` y esas copias no se pueden borrar desde este brief (solo permite los cuatro módulos de F5-09). Hay dos implementaciones de las mismas funciones; si cambia una, hay que cambiar la otra, y F5-10 (o una limpieza posterior) debería borrar el puente y apuntar `pointer.rs` a `Menu::{save, start_test, begin_text_edit, set_slider_from_x, set_meter_from_x}`.
- `model/menu/edit.rs` depende de `paint::hotkey_field` (F5-12). Es lógica pura y compila, pero invierte la capa; si F5-12 mueve ese módulo, hay que actualizar el `use` de `edit.rs`.
- Un `on_save` que entre en pánico no se captura: Rust no tiene el `except Exception` del Python, así que un callback que falle aborta el hilo de UI (misma limitación anotada en F5-07/F5-08).
- `as_float` solo difiere del Python si una clave de slider guardara `None` o texto; `MenuSettings` la normaliza a `Float`, así que no se alcanza desde la API.

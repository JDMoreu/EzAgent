## Decisiones
- `// DECISION` en `ui.rs::HudChatUi`: `hud` es `Weak<DropUI>` porque `DropUI` guarda el panel, el panel guarda `ChatUi` y un `Arc` fuerte filtraría toda la app (Python lo recoge por su colector de ciclos). Si el HUD ya no existe, el adaptador devuelve valores neutros.
- `// DECISION` en `chat_wiring.rs::install_chat`: se inyecta el panel con `set_chat_panel` porque en Rust `DropUI` arranca con `NoChat`; Python lo crea dentro de `DropUI.__init__`.
- `// DECISION` en `host.rs::load_image`: solo se decodifica PNG con la crate `png` que ya declara `ez-app`; GIF/JPEG/BMP/WebP muestran el marcador «No puedo mostrar esta imagen». Python usa Pillow. Ver «Pendiente o riesgos».
- `// DECISION` en los tests: el servidor HTTP local de prueba es un `TcpListener` de un solo uso (no hay `tiny_http` en `ez-app`), con el mismo papel que el servidor local de los tests de Python.
- `ChatUi::bar_scale` devuelve `DropUI::bs()` (`escala de pantalla × tamaño de barra`), que es el `ui.bs` de `chat_ui.py`, no `DropUI::bar_scale`.
- Las raíces y el atajo se fijan al arrancar, como los atributos `chat_roots`/`chat_hotkey` de Python; el resto del estado (pose, llamada, tema, tamaño, fluido) se lee en vivo del HUD.
- `chat_size` solo se aplica si ancho y alto son mayores que cero, con el mismo orden que `__init__`.

## Pendiente o riesgos
- No se abrió una ventana real del chat en la validación (no hay sesión gráfica en automatización): el panel, la `ChatView` y el pintado sí se ejercitan con el modelo real, pero la creación nativa de `ChatWindow` y el repintado por hilo quedan verificados solo por los tests de `ez-hud` (F5-15) y por compilación.
- Imágenes: solo PNG se decodifican; el resto muestra el marcador de imagen no disponible. `ez-hud` declara `image` pero no expone decodificación; si se quiere paridad completa con Pillow, hace falta una función pública en `ez-hud` o añadir `image` a `ez-app`.
- `HudChatUi::make_view` clona la conversación en cada fotograma (`ChatModel::snapshot`), igual que advertía F5-15; con historiales muy largos conviene añadir `version()` al rasgo o un adaptador con caché.
- El ciclo de vida del panel depende de `DropUI::render_frame` para llamar `poll`; si la barra dejara de pintarse sin ocultarse, una ventana de chat cerrada tardaría en retirarse. `hide`/`close` llaman `close_now`, así que el caso normal está cubierto.
- El «historial guardado de `history.db`» del brief es, en el Python y en el puerto, `%APPDATA%/EzAgent/history/chat.jsonl` (F3-14); no se cambió esa ruta.

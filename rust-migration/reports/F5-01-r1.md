## Decisiones
- `layered.rs` pasaba de 600 líneas tras `cargo fmt`: se dividió en `layered/{types,paint,run}.rs`, como permite el brief para módulos grandes.
- `available()` devuelve `cfg!(windows)`: los prototipos de `ctypes` ya no existen (los declara el crate `windows`), así que el resultado es el mismo que el Python en Windows.
- `enable_dpi_awareness()` devuelve `bool` (el Python ignora el resultado); sirve para registrar si funcionó.
- La API pública entrega **RGBA sin premultiplicar** y `layered` hace la conversión a **BGRA premultiplicado** con redondeo `(c*a + 127) / 255`. El Python recibía el BGRA ya premultiplicado de `render()`; al mover el dibujo a `paint/`, la conversión vive aquí (lo pide el brief).
- Las respuestas que el Python devuelve desde las sobrescrituras (`on_pointer_down`, `on_wheel`, `cursor_hand`, `cursor_ident`, `clamp_position`, teclado…) se portan como el trait `WindowHooks`; las notificaciones sin valor (`on_click`, `on_files`, `on_focus_lost`, `on_dpi_changed`, `on_window_drag_*`) van por el canal `mpsc` de `WindowEvent`. `_moved_cb` y `_right_cb` son `DragEnd` y `RightClick`.
- `_on_owner`/`_run_owned_calls` se sustituyen por estado + `PostMessageW(WM_NULL)`: el hilo de la ventana aplica show/hide/move/teclado en cada vuelta. Mismo efecto (nunca se espera al hilo dueño) con menos código.
- Los handles Win32 (DC, HBITMAP, HGDIOBJ y bits del DIB) se guardan como `usize` en el estado compartido para no necesitar `unsafe impl Send`.
- `wheel_follows_pointer()` asume Windows 10/11 (único objetivo del proyecto) y omite `sys.getwindowsversion()`: si falta el valor del registro y la clave es legible, la rueda sigue al puntero.
- Un `WM_CHAR` con sustituto suelto se ignora (`char::from_u32` no lo representa); el Python lo entregaba como `str` con sustituto.
- `stop()` une el hilo sin el plazo de 2 s del Python: `std::thread::JoinHandle` no admite timeout y el bucle despierta como mucho cada ~16,7 ms.
- `monitor_for_point` es la versión pura de `MonitorFromPoint(MONITOR_DEFAULTTONEAREST)`: contiene el punto o el más cercano por distancia euclídea al rectángulo (empate: el primero).
- `WindowOptions::mouse_hook` reproduce a las subclases que omiten `_install_mouse_hook` cuando `wheel_follows_pointer()` es cierto.

## Pendiente o riesgos
- Sin sesión gráfica en la validación: lo puro está probado; la creación real de la ventana, el DIB, `UpdateLayeredWindow`, el gancho `WH_MOUSE_LL` y el portapapeles solo se compilan (como pide el brief).
- El render ya no es un método de la ventana: `paint/` debe construir `RgbaFrame` (RGBA recto) y llamar a `present`; si un futuro módulo produce RGBA premultiplicado (como los buffers internos del Python), habría que exponer una variante que no vuelva a premultiplicar.
- `FrameStats` escribe con `tracing::info!` cuando hay un suscriptor; sin él, el resumen solo se ve por `frame_summary()`.
- Rarezas del Python reproducidas/anotadas (no toqué `rust-migration/python-quirks.md`, fuera del brief): `_WINDOWS[wid]` se registra **después** de `CreateWindowExW`, así que la búsqueda de `WM_NCCREATE` nunca encontraba la instancia (aquí se registra antes); `stop(destroy=True)` publica `WM_CLOSE` después de unir el hilo, así que el mensaje se descarta y la ventana la destruye el bucle; `_WM_SETFOCUS`, `_SWP_NOZORDER`, `_ACCENT_DARK` y `_ACCENT_LIGHT` están definidos y nunca se usan (no se portaron los dos últimos por no ser públicos ni usados); `_lbutton_down` devuelve `True` si la consulta falla, algo que `GetAsyncKeyState` no puede provocar aquí.
- `wheel_follows_pointer()` no consulta la versión de Windows; en un Windows anterior a 10 con el valor ausente diría `true` (el proyecto no soporta esos sistemas).

## Decisiones
- `// DECISION`: el formato del escenario es propio de `ez-fakes` (el brief no lo especifica); es un objeto con `model`, `chunk_chars`, `turns[]` y `fallback`. Cada turno puede ser texto, herramientas, error HTTP, corte (`max_chunks`) o pausa. Queda documentado en `examples/README.md` para F1-12.
- `// DECISION`: al agotarse el guion se responde con `{"content":"Fin del guion.","finish_reason":"stop"}`, salvo `fallback` explícito, para que un E2E siempre termine en vez de quedarse en bucle.
- `// DECISION`: el servidor de `fake-llm` atiende en serie (tiny_http entrega uno a uno); el contador de turnos no necesita lock y el orden de `requests.jsonl` es el de llegada. Un SSE lento bloquea las demás peticiones, aceptable para un servicio de prueba.
- `// DECISION`: `fake-llm` rechaza `--port 0`; sin una línea impresa con el puerto real, el binario no podría comunicarlo. `fake-whisper` sí acepta 0 e imprime el puerto que asigna el sistema.
- `// DECISION`: en `requests.jsonl` solo se anotan las completaciones (no `/health` ni `/models`), que es lo que se compara; `raw_body` conserva el texto exacto y `body` el JSON parseado. Las cabeceras se filtran y la clave nunca se escribe (probado).
- `// DECISION`: el corte a mitad se hace truncando la lista de eventos SSE (`max_chunks`), sin `[DONE]`/`message_stop`; así sirve tanto para texto como para argumentos de herramienta y para ambos protocolos.
- `// DECISION`: `fake-whisper` demuestra salud con `GET /health` además del TCP que usa `ensure_whisper`; el hash gana al orden y no consume el guion. Al agotarse devuelve texto vacío salvo `repeat_last`.
- `// DECISION`: SHA-256 se implementa en el crate (no se añade `sha2`); el escenario se puede generar con `hashlib.sha256` de Python.
- `// DECISION`: `fake-hc` guarda el estado en `<estado>.lock` (`create_new`, 400 intentos × 5 ms) porque el vigía Python consulta `ls` cada segundo mientras la app puede enviar texto; sin el cerrojo, la última escritura perdía entradas. Probado con 8 hilos.
- `// DECISION`: `send` de una línea de comando de agente deja la terminal en `idle` con la pantalla del TUI (el programa ya arrancó); la tarea posterior la pone en `working`. Así `wait_ready`/`finish_launch` del Python funcionan como con un agente real.
- `// DECISION`: `done_after_ms` arranca el reloj en el primer sondeo que ve `working`, para que el vigía observe primero `working` y luego `idle`; `done_after_reads` sigue disponible para pruebas que no esperan.
- `// DECISION`: `fake-hc` simula los selectores (`/models`, `/effort`, `ctrl+t`) en vez de interpretar el TUI; cubre los `session_commands` de los perfiles y permite probar `configure_agent`.
- `// DECISION`: `put` no copia el archivo (el Python solo usa la ruta devuelta): comprueba que exista y responde con esa misma ruta.
- `// DECISION`: `read` de una terminal inexistente escribe el error por `stderr` y sale con 1 (no JSON), porque `herdr.read_agent` usa la salida como pantalla.
- No se añadió ninguna dependencia ni se tocó ningún `Cargo.toml`.
- No hubo errores del Python que reproducir; `python-quirks.md` queda sin entradas nuevas.

## Pendiente o riesgos
- `fake-hc` no lanza procesos reales ni copia archivos: `run`/`tab.new` crean una terminal simulada y `put` solo valida y devuelve la ruta. Para E2E de procesos hace falta que F1-12 use el estado JSON o un `hc` real.
- No se comparó contra un `hc` real (no está instalado): los formatos se dedujeron de `herdr.py` y `watcher.py`; si el `hc` real devuelve otros campos o códigos, F1-12 lo revelará.
- `fake-whisper` no valida el contenido del WAV ni devuelve `segments`; `stt.py` solo lee `text`.
- `fake-llm` responde el cuerpo SSE completo de una vez (tiny_http con `Content-Length`), no en fragmentos temporizados; el cliente ve los mismos eventos y los cortes son por omisión de eventos, no por cierre de conexión a media escritura. Si F1-12 necesita tiempos entre fragmentos, habría que añadir un `Read` con pausas.
- El escenario de `fake-llm` es un contrato nuevo: F1-12 debe generarlo con `examples/README.md` como referencia.
- `fake-agent` imprime las pantallas y termina; no reacciona al teclado (los escenarios bloqueados son una imagen, no una espera interactiva).

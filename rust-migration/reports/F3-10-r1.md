## Decisiones
- `// DECISION` en `search.rs`: `ddgs` se sustituye por POST a `https://html.duckduckgo.com/html/` con `q` y `kl`; `base_url` es configurable para servidores falsos. `backend` se acepta por compatibilidad con la API, pero solo existe el backend HTML y no cambia la ruta.
- `// DECISION` en `search.rs`: el `Client` de `reqwest` se crea por búsqueda en vez de cachear un motor con lock; `reqwest::blocking::Client` es seguro entre hilos y no hay estado que invalidar. No se reproduce la comprobación de tipo de `query` del proveedor porque el trait recibe `&str`; esa validación queda en el borde JSON de `run_web_search`.
- `SearchUnavailableError` se modela como `SearchError` con `kind = "unavailable"` (constructor `SearchError::unavailable`), no como tipo aparte.
- `// DECISION` en `url.rs`: `is_global` de Rust sigue siendo inestable en el toolchain, así que se portan a mano las redes privadas/no globales de `ipaddress` de CPython 3.11 (base `py-baseline`), incluidas las excepciones `192.0.0.9/32`, `192.0.0.10/32` y las de `2001::/23`.
- `// DECISION` en `fetch.rs`: en vez de reescribir la URL a la IP y añadir `Host`/`SNI`, se usa `ClientBuilder::resolve`, que mantiene Host y SNI del nombre original y fija la conexión a la IP validada (equivalente a F36). Se registran también la variante con punto final para que el pin no se pierda.
- `// DECISION` en `fetch.rs`: sin `encoding_rs` solo se distinguen UTF-8 y Latin-1; `windows-1252` se aproxima a Latin-1 y cualquier otro charset cae a UTF-8 con reemplazo.
- `// DECISION` en `tools_web.rs`: el regex de cierre de `untrusted_content` añade `\x1c`-`\x1f` al `\s` de Rust para igualar `str.isspace()` de Python.
- `// DECISION` en `url.rs`: las credenciales se detectan sobre la autoridad cruda (`@`), porque `Url::username()` no distingue `http://@host/` de una URL sin usuario.
- Los estados de redirección seguidos son 301/302/303/307/308; sin cabecera `Location` la respuesta se trata como página normal (comportamiento de `httpx.is_redirect`). Con `Location` vacía se devuelve «La página devolvió una redirección sin destino.».
- No se portó la costura `transport=` de `run_fetch_page`: las pruebas usan un `TcpListener` local y `block_private_ips = false`, como pide el brief. Tampoco se puede representar el error «formato no válido» de `_clean_results` porque el trait devuelve `Vec<SearchResult>` tipado.

## Pendiente o riesgos
- El HTML de DuckDuckGo no es una API estable; el parseo (`div.result`, `a.result__a`, `.result__snippet`) se valida con un servidor falso. Si DuckDuckGo cambia el marcado, habrá que ajustar el selector (anotado como decisión, no como dependencia nueva).
- El cálculo de IPs sigue CPython 3.11. Si el baseline sube a 3.12+/3.13, cambian algunas redes (`192.0.0.0/24`, rangos nuevos) y hay que actualizar la tabla.
- `windows-1252` se decodifica como Latin-1 (difieren en 0x80–0x9F); solo afecta a texto de páginas con ese charset declarado.
- No se piden ni descomprimen respuestas gzip/deflate (no hay feature en `reqwest`); si un servidor comprime sin que se lo pidamos, el texto saldría binario. `reqwest` no envía `Accept-Encoding` con estas features, así que el caso no debería darse.
- `run_fetch_page` recibe `max_chars` obligatorio en Rust; el valor por defecto configurado se aplica en el manejador de la herramienta (igual que `_fetch_handler` en Python). El `run_fetch_page` público de Python con su valor 8000 no tiene un gemelo directo.
